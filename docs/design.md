# design.md — MVP 設計

> 状態: **L8 まで完了（stopped）**。仕様は `spec.md` が正本。デモ子どもは 3年生。  
> L8 まで `main` にマージ済み。次ループは人間がテーマを出すまで提案しない。

## 技術構成

| 層 | 採用 | 理由 |
| --- | --- | --- |
| API | FastAPI / Python 3.12 | 指定スタック。MVP を速く閉じる |
| UI | React 18 + Vite + TypeScript | 指定スタック。HMR でループが速い |
| スタイル | Tailwind CSS + shadcn 風プリミティブ | 子ども向けにテーマを上書きしやすい |
| DB | SQLite + SQLAlchemy 2 | 追加サービス不要。家庭 1 件の MVP に十分 |
| 認証 | なし（デモ家庭 ID=1、ロール切替） | 1 週間 MVP。後から世帯ログインを載せる |

フロント開発サーバが `/api` をバックエンドへプロキシする。

- UI: `http://127.0.0.1:48221`
- API: `http://127.0.0.1:48222`

### L2 で実装したもの（完了）

学習計画の作成・一覧・完了まで。ポイントとアルバムは触らない。

- テーブル `study_plans`（子どものメンバーに紐づく）
- デモシード: 今週の計画が数件（過去日は済み、今日以降は未完了）
- API: 一覧 / 作成 / 更新 / 削除 / 完了
- 画面 `/plan`: 今日＋今週。子どもは「できた」、保護者は追加・直す・消す
- ホームに「きょうのけいかく」を出す
- 今週 0 件なら「まだ予定がないよ。おうちの人につくってもらおう」

#### L2 の API

ロールは既存どおりクエリ `role=child|parent`。未指定は `child`。

| メソッド | パス | だれ | 用途 |
| --- | --- | --- | --- |
| GET | `/api/plans?from=&to=` | 両方 | 期間の一覧。省略時は今週（月〜日、JST） |
| POST | `/api/plans` | 保護者のみ | 作成（日付・科目・内容・目安分） |
| PATCH | `/api/plans/{id}` | 保護者のみ | 直す。完了済みも直せる |
| DELETE | `/api/plans/{id}` | 保護者のみ | 消す |
| POST | `/api/plans/{id}/complete` | 両方 | `completed_at` を今にする。済みは 409 |

子どもが作成・更新・削除すると 403。

#### L2 の `study_plans`

| 列 | 内容 |
| --- | --- |
| id | PK |
| member_id | みんすけ |
| plan_date | 日付（JST の暦日） |
| subject | 科目（こくご / さんすう / りか / しゃかい / そのた） |
| title | 内容（短文） |
| minutes | 目安分（正の整数） |
| completed_at | 完了日時。未完了は NULL |

完了の取り消しは MVP では作らない。

#### L2 でやらなかったこと

- ポイント付与（`plan_complete` は L4）
- アルバム自動記録（L5）
- ドリル、ポイントルール、ごほうび
- 計画の自動生成

### L3 で実装したもの（完了）

計算ドリルの出題・採点・結果まで。ポイントとアルバムは触らない。学年はみんすけの **3年生** を使う。

- テーブル `drill_sessions` / `drill_questions`
- API: 開始（10問生成）/ 1問解答 / 履歴
- 画面 `/drill`: 子どもは種類を選んで 10 問。保護者は履歴
- その場 ○×。終わりに正解数とかかった時間。全問正解は祝う（点は付けない）
- わりざんは割り切れる問題だけ
- 正解はサーバ側。子どもが画面から答えを書き換えられない
- 履歴 0 件なら「まだ 1かいも やってないよ」

#### L3 の API

| メソッド | パス | だれ | 用途 |
| --- | --- | --- | --- |
| POST | `/api/drills/start` | 子ども | 種類を指定して 10 問。進行中セッションがあればそれを返す |
| GET | `/api/drills/{id}` | 両方 | 出題（正解は未解答の問には出さない） |
| POST | `/api/drills/{id}/answer` | 子ども | 1 問採点。最後でセッション終了 |
| GET | `/api/drills/history` | 両方 | 新しい順の履歴 |

保護者が start / answer すると 403。種類: `たしざん` / `ひきざん` / `かけざん` / `わりざん`。

#### L3 のテーブル

`drill_sessions`: kind, grade, status(`in_progress`/`finished`), correct_count, duration_sec, started_at, finished_at  
`drill_questions`: seq(1-10), 式, 正解, 子ども入力, 正誤

出題範囲は既存の「ドリル出題ルール」（3年生: たしざん/ひきざんは 3 桁、かけざんは 2桁×1桁、わりざんは 2桁÷1桁）。

#### L3 でやらなかったこと

- ポイント付与（`drill_complete` / `drill_perfect` は L4）
- アルバム自動記録（L5）
- 弱点分析、解説、学年の画面変更
- 保護者による出題開始

### L4 で実装したもの（完了）

家庭ごとのポイントルール・ごほうび・残高。アルバムは触らない。計算はサーバ側のみ。

- テーブル `point_rules` / `rewards` / `point_ledger`
- デモシード: 既定ルールとごほうび、残高が空に見えない程度の履歴
- 計画完了・ドリル完了（全問正解ボーナス含む）でルールどおり付与
- 画面 `/points`: 子どもは残高・バー・交換。保護者はルール・ごほうび・スタンプ
- ホームにいまの残高
- 残高不足の交換は 400。「あと○点」
- 子どもが点数を直接書き換えられない

#### L4 の API

| メソッド | パス | だれ | 用途 |
| --- | --- | --- | --- |
| GET | `/api/points/summary` | 両方 | 残高、次のごほうびまでのバー |
| GET | `/api/points/ledger` | 両方 | 増減の履歴 |
| GET/PUT | `/api/points/rules` | 取得は両方、更新は保護者 | 付与ルール |
| GET/POST | `/api/points/rewards` | 取得は両方、作成は保護者 | ごほうび |
| PATCH/DELETE | `/api/points/rewards/{id}` | 保護者 | ごほうびの更新・削除 |
| POST | `/api/points/rewards/{id}/redeem` | 子ども | 交換（即時減点） |
| POST | `/api/points/stamp` | 保護者 | できたねスタンプ |

既存の `POST /api/plans/{id}/complete` とドリル終了時に、有効なルールがあれば台帳へ加算する。

#### L4 の既定ルール

| key | 既定 |
| --- | --- |
| `drill_complete` | 10pt |
| `drill_perfect` | +5pt |
| `plan_complete` | 8pt |
| `stamp` | 3pt |

カスタムルールは `custom_<短いid>`。ON/OFF・点数変更・追加・削除ができる。無効または 0 点なら付与しない。

#### L4 でやらなかったこと

- アルバム自動記録（L5）
- 交換の保護者再承認
- 子どもがルールや点数を編集すること

### L5 で実装したもの（完了）

できたことのタイムライン。写真は作らない。

- テーブル `album_entries`
- 自動記録: 計画完了 / ドリル完了 / ごほうび交換 / できたねスタンプ
- 保護者が短い思い出メモを足せる（子どもはメモ追加できない）
- 画面 `/album`: 新しい順。種類は絵文字で区別
- 0 件なら「最初のページは、これからつくられるよ」
- デモシードで数件入っている

#### L5 の API

| メソッド | パス | だれ | 用途 |
| --- | --- | --- | --- |
| GET | `/api/album` | 両方 | 新しい順のタイムライン |
| POST | `/api/album` | 保護者 | 思い出メモ |

自動エントリは既存の計画完了・ドリル終了・交換・スタンプの処理から書く。`kind`: `plan` / `drill` / `redeem` / `stamp` / `memo`。

絵文字案: 計画📒 ドリル✨ 交換🎁 スタンプ🏅 メモ📝

#### L5 でやらなかったこと

- 写真アップロード
- SNS 共有
- エントリの削除・編集（メモ追加以外）

### L6 で実装したもの（完了）

自分で足したルールを消せる。学校の出来事にも、選んだルールで点を渡せる。

- カスタムルールに「けす」。ほぞんすると消える
- スタンプで付与するルールを選べる（できたねスタンプ / テスト100点 など）
- デモシードに「テスト100点」を1件入れる
- 付与は既存の台帳とアルバム（スタンプ扱い）に乗る

#### L6 の API

既存の `POST /api/points/stamp` に任意の `event_key` を足す。省略時は今どおり `stamp`。有効なカスタムルールか `stamp` だけ。計画・ドリルの自動キーは指定できない。

`PUT /api/points/rules` は今どおり、ペイロードに無いカスタムルールを消す。画面からけすと送らない。

#### L6 でやらなかったこと

- 自動ルール（計画完了・ドリル完了など）の削除（オン/オフのまま）
- 子どもが自分で点を付けること
- 学校連携や成績の自動取込
- README の仕上げ（L7）

## ドメインモデル

```
Household 1──* Member (parent | child)
Household 1──* PointRule
Household 1──* Reward
Member(child) 1──* StudyPlan
Member(child) 1──* DrillSession 1──* DrillQuestion
Member(child) 1──* PointLedger
Member(child) 1──* AlbumEntry
```

### 主要テーブル

- `households`: 家庭名
- `members`: 表示名, role(`parent`/`child`), grade(1-6, 子どものみ)
- `study_plans`: 日付, 科目, タイトル, 目安分, 完了日時
- `drill_sessions`: 種類, 学年, 状態, 正答数, 所要秒
- `drill_questions`: 式, 正解, 子ども入力, 正誤
- `point_rules`: event_key, ラベル, 点数, 有効フラグ
- `rewards`: 名前, 必要点数, 有効フラグ
- `point_ledger`: 増減, 理由, 関連 ID
- `album_entries`: kind, タイトル, 本文, スタンプ

### ポイント event_key（初期シード。保護者が改変可）

| key | 既定 |
| --- | --- |
| `drill_complete` | ドリル 1 回 10pt |
| `drill_perfect` | 全問正解 +5pt |
| `plan_complete` | 計画 1 件 8pt |
| `stamp` | できたねスタンプ 3pt（保護者が任意付与） |

カスタムルールは `custom_<uuid短縮>` を key にする。自動イベントには使わず、保護者の手動スタンプや将来拡張の受け皿。

ポイント計算はサーバ側のみ。ルールが無効または 0 点なら付与しない。交換は残高不足なら 400。

## ドリル出題ルール

10 問、重複少なめの整数計算。わりざんは割り切れる問題のみ（MVP）。

| 学年 | たしざん/ひきざん | かけざん | わりざん |
| --- | --- | --- | --- |
| 1 | 1 桁（ひきざんは負にしない） | 使わない（2 の段までなら可） | なし→たしざんにフォールバック |
| 2 | 2 桁（100 未満） | 九九 | 九九の逆 |
| 3 | 3 桁 | 2桁×1桁 | 2桁÷1桁 |
| 4-6 | 3 桁、繰り上がり多め | 2桁×2桁 | 3桁÷1桁 |

## UI トーン

クリーム地、みかん色の主ボタン、空色のサブ、大きな丸角。コピーは子どもに敬語を使いすぎない。「できたね」「もういっかい」を標準にする。
