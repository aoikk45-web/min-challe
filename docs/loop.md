# loop.md — 人間承認つきループ

`minsuke-springboot_02` 型: **AI は1ループ分だけ進め、人間が承認してから次へ。**

```
        人間 GO
            │
            ▼
  [PM 要件] → [設計草案] → ★ゲートA 人間承認
            │
            ▼
  [実装] → [テスト] → [レビュー要約] → ★ゲートB 人間承認
            │
            ▼
      次ループの提案へ（またゲートA）
```

コードを書くのは **ゲートA 通過後〜ゲートB 提示まで** だけ。  
ゲートの外ではドキュメントの提案と質問以外をしない。

## 1ループの中身

### ゲートA 前（提案。コード禁止）

1. 進行役が `docs/gate.md` を `waiting-A` にする。
2. PM が「このループで何ができるようになるか」を 5 行以内で書く。
3. アーキテクトが影響範囲（触るファイル、API、画面）を書く。
4. 人間に提示して **止まる**。

### ゲートA 後（実装）

5. 実装者が承認範囲だけ実装する。
6. テスターが検証する（失敗したら同じループ内で直す。最大 5 周）。
7. レビュアーが差分要約を `misutes.md` に書く。
8. 進行役が `docs/gate.md` を `waiting-B` にして **止まる**。

### ゲートB 後

- **承認** → バックログを `done` にし、次ループのゲートA 提案を出してまた止まる。
- **差し戻し** → 指摘だけ直す。範囲を広げない。
- **ストップ** → コードを増やさない。

## 外側ループ（提案。未承認）

| ループ | テーマ | ゲートA で承認するもの |
| --- | --- | --- |
| L0 | 進め方と MVP 範囲 | roles / loop / gate / 4本柱の境界。**コードはまだ書かない** |
| L1 | 土台 | FastAPI + React の空アプリ、デモ家庭、起動 |
| L2 | 学習計画 | 計画の作成・完了 |
| L3 | 計算ドリル | 出題・採点 |
| L4 | ポイント制 | 家庭ルール・付与・交換 |
| L5 | 成長アルバム | 自動記録とメモ |
| L6 | 統合 | 子ども/保護者切替、空状態、README |

L3〜L6 の順番は人間が入れ替えてよい。弱点分析は L7 以降で、MVP では提案もしない（聞かれたときだけ）。

## 人間が返す言葉（そのまま使ってよい）

| 入力 | 意味 |
| --- | --- |
| `L0 承認` / `GO` | 今のゲートを通す |
| `差し戻し: …` | 指摘を直して同じゲートに戻す |
| `スコープ変更: …` | このループの範囲を変える |
| `ストップ` | 実装も次提案もしない |

## 報告フォーマット

```
### ゲート: A or B / ループ Ln
- 提案または結果:
- 承認してほしいこと:
- 承認されるまでやらないこと:
```
