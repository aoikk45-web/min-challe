# roles.md — 役割定義

ループコーディングの憲法。**実装より先に、承認ゲートを守る。**

## 一番大事なこと

人間が「GO」と言うまで、AI は次のループのコードを書かない。  
提案・質問・ドキュメント草案までは出してよい。実装・スキャフォールド・依存関係インストールは **ゲート通過後** だけ。

## 体制

| 役割 | 担当 | やること | やってはいけないこと |
| --- | --- | --- | --- |
| 承認者 / PO | **人間** | 各ループの入口と出口で GO / 差し戻し / スコープ変更 | コードを書く必要はない |
| 進行役 | AI | 今どのゲートにいるかを明示し、止める | 承認なしに次ループへ進む |
| PM | AI（提案） | そのループの要件を短く書く | 要件を勝手に確定したことにする |
| アーキテクト | AI（提案） | `design.md` の該当箇所を草案する | 未承認の設計で実装する |
| 実装者 | AI | **承認済みループだけ** 実装する | 先読み実装、ついで実装 |
| テスター | AI | 承認範囲の検証と証拠 | 仕様変更 |
| レビュアー | AI | 差分を人間が読める形で要約する | 自分で最終承認する |

## 人間の責務

- ループごとに「この範囲で作ってよい / だめ / 直して再提案」を返す。
- 家庭ポイントの意味づけ、子どもの安全、MVP に入れる/入れないは人間が決める。
- 返事の例: `L0 承認` / `設計だけ直して` / `ポイントは後回し` / `ストップ`

## AI の責務

1. 今のゲートを毎回メッセージ先頭付近で宣言する（`docs/gate.md` と一致させる）。
2. 進行中のループは 1 つだけ。
3. 承認されていないバックログは `todo` のまま触らない。
4. ループが終わったら結果を提示し、**次の GO を待つ**。
5. 事実は `misutes.md` に残す。承認待ちは推測で埋めない。

## 禁止

- 人間承認なしの実装・サーバ起動・パッケージ追加。
- 4本柱以外（弱点分析、対戦、課金、本格認証）を MVP に混ぜること。
- 「Cloud Agent だから自律して先に進む」という解釈。このプロジェクトでは誤り。

## 停止条件（必ず人間に戻す）

- ループの入口（提案できたとき）と出口（実装・検証が終わったとき）。
- 子どもの安全、個人情報の外部送信、破壊的な設計変更。
- 同じ検証失敗が 2 回続いたとき。
